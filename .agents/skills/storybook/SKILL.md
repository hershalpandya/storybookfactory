# Storybook workflow

Use English for the conversation, instructions and image requests. Ask for the private project location, one or more English UTF-8 transcripts, intended reader and story language, and whether to continue an earlier series (its private catalog and art) or start a new one. Ask about existing progress before creating anything; resume from saved artifacts. Never claim a review, audio check, image generation or physical proof that did not happen. Keep private material outside Git and obtain the owner's agreement before sending it or references to any external service.

Resolve guide paths from the checkout or workflow export root. Read `docs/PROJECT-FORMAT.md`, `docs/LANGUAGE-MODULES.md`, `docs/SCENE-ASSETS.md`, `docs/BOOK-RENDERING.md` and `docs/BOOK-STANDARD.md`. Use `uv run --locked storybook` from the checkout. Keep inputs, source, edition and outputs in separate subdirectories of an ignored project directory. See the checkout README for the layout.

1. For a new book, run `storybook init WORKSPACE --workspace` and read its generated file map. Use `WORKSPACE/source-review` as the source project and `WORKSPACE/book-edition` for the edition. Register each transcript with `storybook register SOURCE FILE`; when there are at least two, use `storybook compare SOURCE`. Inspect differences and source context with the user. The tool does not transcribe or verify audio. Reconcile a private story-only English JSON draft: preserve the narrator's voice, events and foreign phrases; omit unrelated asides; cite transcript IDs and locations; record disputed alternatives and unresolved uncertainty instead of guessing. A human checks fidelity, omissions and citations and explicitly reviews the draft before `storybook review SOURCE DRAFT`. Keep unresolved uncertainty visible.
2. Ask for the story language separately from the English interaction. `storybook languages` lists modules; inspect the selected module. French CE1 has guidance; `test-xx` is only a test fixture. If the requested language lacks support, say so and do not claim it is supported. Prepare the adaptation linked to the source hash and passages. A competent human checks fidelity, natural language, reading level, grammar and every applicable pronunciation mark in context, including French silent letters and liaisons. Record unresolved issues. Only after explicit human approval run `storybook approve-adaptation SOURCE DRAFT` and `storybook check-adaptation SOURCE`. Flags and hashes record assertions and integrity, not certification.
3. Build an ordered ledger from source passages to events and pages. Check omissions, duplication and order with the narrator. Initialize the source project's catalogs with `storybook init-catalogs SOURCE`. Define each character and recurring prop or set element, with conditions, reference views and visible part counts where needed. Import compatible references from earlier projects. Use `docs/EDITIONS.md` to prepare an edition index and metadata, then run `storybook edition import EDITION SOURCE INDEX METADATA` and `storybook edition check EDITION`. Classify every illustration as a recurring setting or a standalone scene in the brief. Use the offline example for sample input files.
4. Read the sibling `storybook-image/SKILL.md` before requesting art. Follow `edition next` and render and stage each recurring setting with `edition set-layout --stage` before the scene dry run. Use `edition check` and the scene handoff to inspect text fit, staging, visible contact and reference order. Journal each provider attempt. Assign art after reviewing the captured image and record its visual review. Store revision operations and recorded approvals with the private project. Save agent review notes under `reports/`. Alternate assignments or revisions can reopen dependent reviews.
5. Run `storybook edition build EDITION --mode reading` for a preview. Review each page for consistency, text and illustration fit, shaped annotations and legibility. Build with `--final` after resolving open art and text layout reviews. Keep `reviewed-text.json` and `proof-report.json` alongside the PDFs. Record owner proof separately. For duplex, print A4 landscape at actual size with short-edge flip. Inspect a test sheet and the physical print and sewing before recording proof.
6. To resume, inspect the source review, `edition.json`, inventory, journals, current revision and output proof before doing new work. Recheck the adaptation and edition, then revisit dependencies the change report identifies. Keep existing output directories. Each default build writes to a fresh folder under `outputs/previews/` or `outputs/final/`.

For an existing `scenes.json` project, see `docs/SCENE-ASSETS.md` and `docs/BOOK-RENDERING.md` for scene-plan commands, or import it into the edition workflow using `docs/EDITIONS.md`.
